AI 平台总体技术架构

原则：平台主权（GFast）+ 可插拔 Runtime（现成框架）+ 单向投影同步。优先复用持续更新的成熟组件，控制面与门户统一在 GFast，Agent 能力通过 Adapter 接入。功能划分见 功能架构图；编码约束见 ARCHITECTURE.agents.md。

GFast 模块 外部现成产品/服务 一期交付 二期增强 三期扩展

一期 可运行最小闭环

  • GFast：登录/RBAC/多公司(一级部门)、资源广场、对话壳(iframe)、Run 中心
  • 接入 Hermes-agent（Runtime）+ Hermes Adapter
  • Projection：模型路由 / MCP 白名单 / 委派身份 → Hermes
  • MCP 治理门（权限、风险、配额、审计）
  • Docker 沙箱隔离；任务表异步调度（暂不上 Temporal）

二期 可靠编排与隔离强化

  • 引入 Temporal（长任务、暂停恢复、审计告警）
  • 按需引入 NATS JetStream（事件解耦）
  • 每租户 / 每 Run 强化 Hermes 进程与目录隔离
  • 完善评测、成本看板、告警
  • 可选企业 SSO（Keycloak / 企业 IdP）前置

三期 多 Runtime 与自动化

  • 接入 OpenCode、QwenPaw、Eino 等更多 Runtime
  • A2A Gateway（跨 Agent 协作）
  • 独立 Browser / Code Worker；E2B 等沙箱
  • Dify 仅作 Legacy 兼容运行时
  • UE / GPU 等专项 Worker（按业务需要）
请求主路径：统一门户 → GFast 身份与鉴权 → Core 立项/记录 →（一期任务表 / 二期 Temporal）→ Runtime Adapter → 沙箱 Runtime → 工具经 MCP 治理门 → 业务/外部资源 → Run 记录回写

关键边界（避免混淆）

  • 资源广场：登记「有哪些」资产（MCP / Skills / 模型 / 插件）
  • Projection：把「本次可用配置」单向下发给 Runtime
  • Adapter：一次 Run 中如何呼叫 Runtime 并回收事件
  • Gateway：Runtime 使用 Tool 时的权限 / 风险 / 配额安检
  • Worker / 沙箱：终端、文件、浏览器等副作用的实际执行边界

架构约束（禁止项）

  • 为每个概念拆独立微服务（早期交付与维护成本过高）
  • 将第三方 Runtime 源码深度揉进 GFast 并魔改
  • 以 Hermes / 其它框架 Dashboard 作为多公司(一级部门)统一门户
  • 多公司(一级部门)共用同一 Runtime HOME / 会话库
  • Runtime 直连平台主库；透传用户主 JWT
  • 绕过 MCP 治理门调用高危 Tool
  • 一期同时铺开 Temporal + A2A + 多 Worker + 多 Runtime
