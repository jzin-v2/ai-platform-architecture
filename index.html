推荐实施顺序（一人版）

  • ① GFast：资源广场 + Agent 工作台 + Run 记录
  • ② 部署 Hermes 容器 + 写 Hermes Adapter
  • ③ Projection：把模型 Key/路由、MCP 白名单推给 Hermes
  • ④ MCP 治理门：工具调用鉴权/审计/配额
  • ⑤ 沙箱隔离与每用户工作目录
  • ⑥ 有长审批/强恢复需求再上 Temporal
  • ⑦ 再接 OpenCode / QwenPaw（复制 Adapter 模式）

三个最容易混的概念

  • 资源广场：登记「有什么」——在 GFast
  • Projection：把「用哪套配置」推给 Hermes——在 GFast 一个模块
  • Adapter：一次运行时怎么呼叫 Hermes——在 GFast 胶水代码
  • Gateway：Hermes 要用工具时的安检——在 GFast 中间件
  • Worker：危险动作在哪执行——第一期就是 Hermes 容器

禁止（省时间也保安全）

  • 为每个概念拆一个微服务（一人养不动）
  • 把 Hermes/QwenPaw 源码揉进 GFast 大改
  • 用 Hermes Dashboard 当多租户门户
  • 多用户共用一个 Hermes HOME / state.db
  • Runtime 直连业务库；透传用户主 JWT
  • 第一期就上完整 Temporal+NATS+A2A+多 Worker（会拖死交付）
